Shopify Odoo Connector: two-way sync for orders, products, customers, stock and fulfilment

Connect a Shopify store to Odoo and keep both sides in step, on a schedule. Import orders, products, customers and taxes; publish stock levels and fulfilment tracking back. Built on Shopify's GraphQL Admin API, which Shopify has required for new apps since October 2024 and is replacing REST with, so this will not need rewriting when the REST endpoints finish being withdrawn.

The interesting part of a connector is not what it syncs, it is what it refuses to guess. This one never imports an order twice, never drops a tax it has no mapping for, never attaches a sale to a nearly‑matching variant, and never imports a total that disagrees with what the customer actually paid.

What it syncs, and which way

Records Direction Notes
Orders Shopify to Odoo With line discounts, shipping lines and tax lines
Products and variants Either way, or both Options become Odoo attributes; SKU and barcode carried across
Customers and addresses Either way, or both Matched on exact email, country resolved by ISO code
Stock levels Odoo to Shopify Available‑to‑promise or on hand, to a location you choose
Fulfilment and tracking Odoo to Shopify On delivery validation, on invoice posting, or whichever is first
Taxes Mapped by you Anything unmapped stops and asks rather than under‑billing

One store, every setting in one place

Connect with a Shopify custom app token, test the connection, and pull or push anything on demand. Nothing moves until you say so: automatic confirmation, invoicing, stock publishing, fulfilment and the scheduler all start switched off.

You choose which way data travels

Products and customers can each run Shopify to Odoo, Odoo to Shopify, or both. A push against a pull‑only store is refused with a reason rather than done quietly, because a direction is set precisely so the other way cannot happen by accident.

Map any Shopify field to any Odoo field

Every business keeps things in different places, so the mapping is yours to set, validated the moment you type it. Identity fields are deliberately not mappable: repointing those would break duplicate prevention, which everything else rests on.

Runs on a schedule, or right now

A scheduled sync per store, with its own interval and its own choice of what to sync. A store already syncing is never started a second time on top of itself. When something is urgent there is a manual pull and push for every task.

Stock and fulfilment, back to the storefront

Publish available‑to‑promise rather than on hand, so the same unit is not sold twice. Send fulfilments with the tracking number when the delivery is validated, or when the invoice is posted for businesses that never run Inventory. Shopify's shipping email to the customer stays off until you switch it on.

When something fails, you are told what to fix

Every unit of work is a row that keeps the exact payload that caused it, so a retry replays the failure without asking Shopify for the data again. Failures split into the two kinds that need different things from you:

  • Failed is transient, a dropped connection or a rate limit. The scheduler retries it, backing off further each time.
  • Needs attention means something has to change first: a tax with no mapping, a product not in Odoo, an expired token. These are never retried on a timer, because a timer cannot fix them, and each one carries the sentence saying what to do.

Never a silent under‑billing

Shopify calculates tax its own way. Rather than guess, every tax Shopify sends is listed the first time it appears and matched to a real Odoo tax by your accountant. Anything unmapped stops the order instead of producing an invoice quietly short by the tax, which nobody notices until a return is filed.

Requirements

  • Odoo 16, 17, 18 or 19, Community or Enterprise.
  • The free E‑Commerce Connector Engine (Miko) module, which provides the identity mapping and job queue underneath this.
  • A Shopify custom app token with read and write access to products, customers, orders, inventory and locations. read_customers is required even if you only import orders, because an order carries its customer.
  • Odoo Online cannot run modules containing Python, so this needs Odoo.sh or a self‑hosted install.

Tested, not assumed

86 automated tests run against real Odoo 16, 17, 18 and 19 on every release, and every Shopify call in the module was executed against a live Shopify development store on API version 2025‑07 rather than only against mocks.
